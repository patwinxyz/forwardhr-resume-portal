# 線上履歷填寫系統

## 專案簡介

本專案是一套 **純前端線上履歷填寫系統**，使用者可直接在瀏覽器中填寫人事資料表，並於本機端完成預覽、列印與 Word 匯出，不需將履歷內容儲存至後端資料庫。

此設計的核心目標是：

- 降低個資集中儲存風險
- 簡化系統維護成本
- 提供固定格式的人事資料表填寫流程
- 支援下載與列印，方便後續自行傳送

依目前專案內容，履歷表欄位包含姓名、性別、出生日期、年齡、婚姻狀況、居留證號、聯絡電話、電子郵件、居住地址、教育背景、工作經驗、語言能力、證照、交通方式、可接受工作地點、希望工作內容、可接受工作時間、希望待遇與填寫日期。以上欄位與版面配置來自既有的人事資料表模板。fileciteturn3file5

目前前端頁面已具備工作經驗新增/刪除、勾選欄位處理、列印與 Word 匯出等功能。fileciteturn3file6

## 專案目標

### 功能目標

- 提供使用者線上填寫履歷表
- 即時顯示固定格式預覽畫面
- 支援列印
- 支援 Word 匯出
- 不將履歷內容存入資料庫

### 資安與個資目標

- 使用者資料僅存在瀏覽器當前操作階段
- 避免建立後端履歷資料庫
- 避免後台查詢大量個資
- 降低個資外洩與維運風險

---

## 系統定位

本系統定位為：

**履歷填寫與匯出工具**

不是傳統的人才資料庫系統，也不是後台履歷管理平台。

本系統聚焦於：

1. 填寫
2. 預覽
3. 匯出
4. 列印

不處理：

- 會員系統
- 履歷長期保存
- 後端資料查詢
- 招募流程追蹤
- 系統代寄履歷

### 1. 純前端架構

系統主要邏輯在前端執行，履歷資料不需送往後端儲存。

## 建議資料流

### 使用流程

1. 使用者開啟履歷填寫頁面
2. 於瀏覽器中輸入資料
3. 前端即時更新預覽內容
4. 使用者選擇列印或匯出 Word
5. 檔案下載至使用者裝置
6. 使用者自行保存或傳送

### 資料處理原則

- 不寫入資料庫
- 不提供後端履歷儲存 API
- 不建立履歷查詢後台
- 盡量不使用 localStorage 長期保存資料
- 表單資料僅保留於當前瀏覽器操作狀態

---

## 安全與個資保護設計

### 建議原則

1. **不存資料庫**  
   降低集中式個資保存風險。

2. **不將表單資料送往伺服器儲存**  
   避免伺服器端殘留個資。

3. **全站 HTTPS**  
   確保傳輸過程安全。

4. **避免記錄敏感資料到 log**  
   包含姓名、電話、居留證號、地址、Email 等。

5. **下載後由使用者自行管理檔案**  
   系統不保留履歷副本。

6. **正式環境避免使用會蒐集欄位內容的第三方分析工具**  
   避免個資外流到外部服務。

## 專案適用情境

本系統適合以下情境：

- 公司內部招募用固定版型履歷表
- 人力仲介或媒合單位使用的標準化資料表
- 不希望建立履歷資料庫的專案
- 需要快速部署與低維護成本的前端工具

---

## 不適用情境

若有以下需求，則需另行規劃後端系統：

- 長期保存履歷資料
- 建立企業後台查詢系統
- 多人協作審核履歷
- 履歷投遞紀錄追蹤
- 自動寄送履歷給企業
- 與招募流程系統整合

---

## 結論

本專案是一套以 **個資保護、低維護成本、固定版型匯出** 為核心的純前端履歷填寫系統。

透過不將履歷資料寫入資料庫的設計，可有效降低個資集中保存風險；搭配 GitHub 與 Vercel，可兼顧開發效率、部署便利性與後續維護需求。

若後續需要擴充，可再逐步加入 PDF 匯出、模板切換、多語系與更完整的前端驗證機制。
